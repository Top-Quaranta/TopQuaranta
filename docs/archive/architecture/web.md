# Web (Django public surface)

The leftover Django responsibilities after Sprint 4's React flip
(April 2026). The SPA in `web-react/` owns the visual site; the
`web/` Django app keeps three narrow surfaces that the SPA cannot
do on its own:

1. **Error pages** rendered by Django when a Django-side URL hits
   a 403/404/500 (the SPA renders its own client-side 404 for the
   paths Caddy serves to it).
2. **RSS feeds** at `/rss/top.xml` and `/rss/novetats.xml`.
3. **XML sitemap** at `/sitemap.xml` plus a handful of sub-sitemaps.

The DRF API at `web/api/` is documented separately at
`docs/architecture/api-versioning.md`; the SEO meta-tag + OG-image
service at `web/seo/` is at `docs/architecture/seo.md`; staff
endpoints at `web/api/staff/` are at `docs/architecture/staff.md`.
This doc covers the rest.

## Directory layout

```
web/
├── apps.py
├── views/                  Module package; today only error handlers.
│   └── __init__.py         handler_403 / handler_404 / handler_500
├── feeds.py                Atom 1.0 feeds (RSS surface)
├── sitemaps.py             sitemap-index + 6 sub-sitemaps
├── legal_versions.py       TERMES_VERSIO constant
├── templates/
│   ├── web/                403.html, 404.html, 500.html, robots.txt
│   └── seo/                Meta + JSON-LD templates (used by web/seo/)
├── static/                 Brand images served by Caddy + Django
├── api/                    DRF API. See api-versioning.md + staff.md.
├── seo/                    SEO service. See seo.md.
└── tests/                  Pytest suite for the above
```

The pattern post-Sprint-4: every former template view (homepage,
ranking, artistes, perfil_artista, perfil_album, mapa,
com_funciona) was removed from `web/views/__init__.py` along with
`web/urls.py`. The SPA renders these client-side from the same
DRF endpoints anyone else calls; Django no longer renders any
public page.

## Error handlers

`topquaranta/urls.py` wires `handler403`, `handler404`, `handler500`
to functions in `web/views/__init__.py`. They fire only when a
Django-side path raises (so `/api/*`, `/compte/2fa/*`,
`/compte/activar/*`, `/sitemap.xml`, `/robots.txt`, the RSS feeds).
Everything else hits the SPA at Caddy level and React Router
handles 404 client-side.

Templates intentionally minimal (no shared base extending the SPA
layout) so a server-side error never depends on the SPA bundle
loading.

## RSS feeds (`web/feeds.py`)

Two Atom 1.0 feeds, both honour the shared distribution gate
`ConfiguracioGlobal.pot_publicar("rss")` (the master `distribucio_activa`
AND `rss_actiu`) — returning 503 when off (2026-06-07; was `rss_actiu`
alone):

| Path | Window | One item per |
|---|---|---|
| `/rss/top.xml` | Last 12 weeks | Week, with top-10 entries inline |
| `/rss/novetats.xml` | Last 30 days | Newly verified release |

Django's `Feed` class (not hand-rolled XML) is used because the
Atom1Feed writer handles ETag/Last-Modified automatically and
escapes Catalan diacritics correctly.

## Sitemaps (`web/sitemaps.py`)

Sprint S Block B (2026-05-06) expanded the surface from 5 static
URLs to a sitemap-index referencing 6 sub-sitemaps. Total ~2 k
artistes + thousands of albums + thousands of cançons + 8
territoris + ~52 weekly tops × 8 territoris ≈ tens of thousands of
URLs.

Each sub-sitemap caps at the Google-recommended 50 k URLs per
file; the index returns one entry per sub-sitemap with a
`lastmod` derived from the latest row mtime so crawlers only
re-fetch when something actually changed.

## Legal versions (`web/legal_versions.py`)

Single source of truth for `TERMES_VERSIO`. Bumped whenever the
public legal pages change materially (new processor, new purpose,
new data category). Consumed by `comptes/` to mark consent
freshness on `PerfilUsuari.consent_termes_versio`. Conventionally
ISO date (`YYYY-MM-DD`).

## Static files

`web/static/` holds brand images and the `og/` PNGs generated by
the SEO service. Caddy serves them directly from
`/home/topquaranta/app/staticfiles/` after `collectstatic`; Django
hits them only in DEBUG.
